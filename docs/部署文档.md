# 部署文档

本文档介绍 PBL 智能课程咨询服务（CourseAgent）的部署方法。推荐使用 Docker Compose 一键部署；本地开发部署见第 3 节。

## 1. 架构与环境要求

### 1.1 服务组成

| 组件 | 技术 | 说明 |
|---|---|---|
| 后端 API | FastAPI + Python 3.8 | 入口 `uvicorn app.main:app`，端口 8000 |
| 前端 | React 18 + Vite + Ant Design 5 | 构建产物由 FastAPI 单端口托管 |
| 关系数据库 | MySQL 8.0 | 业务数据、会话历史、用户画像、向量元数据 |
| 缓存 | Redis 7 | 短期记忆、限流、验证码、分布式锁（单机可留空降级） |
| 反向代理 | Nginx | TLS 终结、SSE 透传、上传放行 |
| 监控 | Prometheus + Alertmanager | 指标抓取与告警（可选） |

### 1.2 环境要求

- Docker 24+ 与 Docker Compose v2（容器部署方式）
- 或：Python 3.8.x、Node.js 20+、MySQL 8.0、Redis 7（本地方式）
- 需要可访问通义千问 DashScope 服务（公网或专线）

## 2. Docker Compose 部署（推荐）

### 2.1 准备配置文件

```bash
cp env/config.env.example env/config.env
cp env/qianwen_config.env.example env/qianwen_config.env
```

编辑 `env/config.env`，至少修改以下项：

- `host=mysql`（容器网络内必须使用 compose 服务名）
- `password=` 填入数据库密码
- `jwt_secret=` 改为随机长字符串，可执行 `python -c "import secrets;print(secrets.token_hex(32))"` 生成
- `cors_origins=` 生产环境填写具体域名白名单
- 如启用邮箱验证码登录，填写 `smtp_host` / `smtp_user` / `smtp_password`

编辑 `env/qianwen_config.env`：

- `api_key=` 填入真实的 DashScope API Key
- `model=` 按需选择模型（如 `qwen-plus`）

### 2.2 注入 MySQL 密码并启动

MySQL root 密码必须通过环境变量显式注入，未设置时 compose 拒绝启动：

```bash
# Linux / macOS
export MYSQL_ROOT_PASSWORD="你的强密码"
# Windows PowerShell
$env:MYSQL_ROOT_PASSWORD="你的强密码"

docker compose up -d --build
```

首次启动时 MySQL 会自动执行 `course.sql` 完成建库建表。

### 2.3 TLS 证书（对外提供服务时）

将证书放置到：

- `nginx/certs/fullchain.pem`
- `nginx/certs/privkey.pem`

公网域名可用 certbot 签发 Let's Encrypt 证书；内网测试可用 openssl 自签。证书就绪后 Nginx 暴露 80/443，其余服务均不对外暴露。

### 2.4 验证

| 检查项 | 方式 |
|---|---|
| 服务状态 | `docker compose ps`（全部为 healthy） |
| 存活探针 | `GET /healthz` |
| 就绪探针 | `GET /readyz`（检查 MySQL 连通性） |
| 页面访问 | 浏览器打开 `http://服务器地址/`（配置证书后用 https） |
| 指标 | `GET /metrics`，Prometheus 抓取配置见 `monitoring/prometheus.yml` |

### 2.5 常用运维命令

```bash
docker compose logs -f api      # 查看后端日志
docker compose restart api      # 重启 API
docker compose down             # 停止并移除容器（数据卷保留）
```

数据备份与恢复：

```bash
bash scripts/backup.sh    # 备份 MySQL
bash scripts/restore.sh   # 恢复备份
```

## 3. 本地开发部署

### 3.1 初始化数据库

创建数据库并导入建表脚本：

```sql
CREATE DATABASE db_course DEFAULT CHARACTER SET utf8mb4;
```

```bash
mysql -u root -p db_course < course.sql
```

如使用 Alembic 管理迁移（可选，用于增量升级）：

```bash
python -m alembic upgrade head
```

### 3.2 启动后端

```bash
pip install -r requirements.txt
python -m uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
```

配置文件准备同 2.1（本地方式 `host` 保持 `localhost`）。

### 3.3 启动前端

开发模式（热更新，5173 端口自动代理 API 到 8000）：

```bash
cd web/frontend
npm install
npm run dev
```

生产构建（产物 `dist/`，由后端在 8000 端口单端口托管）：

```bash
cd web/frontend
npm run build
```

> 不构建前端也可正常使用，系统自动退化为纯 API 服务。

## 4. 端口说明

| 端口 | 服务 | 备注 |
|---|---|---|
| 8000 | 后端 API / SPA | 单端口模式，容器部署时仅对 Nginx 暴露 |
| 5173 | 前端 dev server | 仅本地开发使用 |
| 80 / 443 | Nginx | compose 部署的唯一对外入口 |
| 3306 / 6379 | MySQL / Redis | 仅容器内网可达 |
| 9090 / 9093 | Prometheus / Alertmanager | 默认仅绑定宿主机回环地址 |

## 5. 生产上线安全检查清单

- [ ] `MYSQL_ROOT_PASSWORD` 使用强密码并通过环境变量注入
- [ ] `jwt_secret` 已替换为随机长字符串
- [ ] DashScope API Key 仅存在于 env 文件或环境变量中，未写入代码
- [ ] `cors_origins` 已收敛为具体域名白名单
- [ ] 对外服务启用 HTTPS（Nginx TLS）
- [ ] 数据库使用最小权限账号，业务库不长期使用 root
- [ ] 已配置定期备份（scripts/backup.sh）并验证可恢复
- [ ] 确认 `logs/` 与 `storage/`（`storage/uploads/`、`storage/chromadb/`）使用持久化卷挂载
